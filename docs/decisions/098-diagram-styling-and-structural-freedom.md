# Diagram styling and structural freedom

Date: 2 November 2026

## Owner instruction

> Please update the brief so it governs visual styling without restricting diagram types or layouts, then revise the Regix roadmap diagrams to use the most appropriate format for what each one needs to explain.

## Ruling

The visual system governs typography, tokens, contrast, spacing, emphasis and accessible presentation.
Diagram types, topology, node counts and layouts follow the relationships or process being explained.
The gallery and built-in renderer provide reusable examples, not an exhaustive catalogue. No separate
exception is required solely because a diagram uses another type or arrangement.

Scoped SVG or semantic HTML authoring is allowed inside the kit's figure. Semantic shapes and a
consistent symbol family may identify objects or actions. The change does not authorize unrelated
page restyling, decorative imagery or a replacement quantitative chart system. Built-in renderer
schemas and limits still govern that renderer; they do not govern separately authored diagram content.

## Source compatibility

The agent brief explicitly takes precedence for this diagram policy over conflicting clauses in its
pinned specification. The source specification and repository instructions carry the same rule.
Existing asset pins, version numbers, stylesheets, scripts, sample pages and renderer behavior are
unchanged. The retained older branch receives the same policy without a version migration.

## Validation boundary

The existing checks were written for closed component sets and renderer schemas. They have not been
extended by this policy change. Record any conflicting check with its exact region and replacement
requirement, and check that requirement directly. Never report an unrun or failed check as passed.
Source accuracy and semantic completeness require inspection as well as layout and accessibility.
Artifact-specific owner restrictions on visual inspection still apply and must be disclosed.
