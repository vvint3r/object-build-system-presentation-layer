# content-morphia — locked rules (read before any design work)

This project is the "content-morphia" design system. Visual language is LOCKED (option 2a). Read `CONTINUATION.md` + `content-morphia-SPEC.md` before building; keep the SPEC coverage index updated every round.

## Non-negotiables
1. Text is #000 or #fff ONLY. No grey text ever. Hierarchy = Nunito weight 300→900, never tinted color. **Four heading tiers, and mono is not one of them (R19.2):** T1 page title 900/44 · T2 section title 900/28 · T3 container heading 800/21 sentence case, lh 1.3, ls −.01em — the heading of any container, card, callout, figure or table, and it must outrank its own rows: where a container's body rows are at body size they are set at 400, never 700 (R28.4) · T3b sub-block title 700/17 sentence case, the one rung under T3, used after a corner bracket and nowhere else · T4 body 400/15.5. **A heading smaller than the body it introduces is the defect this tier list exists to prevent (R36.2):** T3 was 700/15 against 15.5px prose, which made every container heading disappear into its own contents. **Two tiers at the same size is the same defect one level up (R36.11):** a page that authored its section titles at 800/21 collides with T3 the moment T3 is raised, so a section title and a card heading become indistinguishable. T2 must outrank T3 on every page, and a page whose section titles sit below 900/28 is raised to it rather than the tier below being lowered. A mono label is never a container's sole heading. A bullet's explanatory sub-line is body 14px, never mono. **Specimen commentary (R28.5)** — the sentences describing a specimen rather than being it — is 14px and separated from the specimen by a 1px #ebebeb rule at 28px clearance, so the specimen's own attribution cannot be read as commentary. Attribution binds up: 6px below the thing it attributes, prefixed by a mono label, never by a dash. **A container's identity label never shares a line with its heading (R36.3):** the label row comes first (identity chip left, at most one status chip pushed right), the heading sits on its own line beneath it, the body follows. A label set beside a heading reads as a peer of the heading rather than a tag on it.
2. Accent #1de9b6 is never text. Only: bars, 1.5px link underlines at 3px offset, borders, chip fills, reserved offset shadow, column washes (rgba .12/.25/.3), list bullets, **and chart data marks — a population is drawn in the accent, never in solid black (R23.7)**. Always redundant with a shape/label/position cue. **One marker per link (R19.5)** — underline or arrow prefix, never both; the arrow prefix belongs to standalone jump lists. **A link is drawn as a link (R28.1):** any in-page or cross-page anchor in a nav strip, rail or sentence carries the 1.5px teal underline at 3px offset. The six group pills are the only unmarked anchors — they are tabs, and the active-tab treatment is their one marker. On-this-page strips carry no scroll-spy bar: an underlined anchor already reads as reachable, and a bar under one of five leaves the other four unmarked. **This holds for every section list, strip or sticky rail (R28.1, scope widened R36.12):** the current item is marked by weight alone, 700 and not a link, with no bar, disc or fill beside it. **Teal bullet ration (R19.6):** only in a scannable list of ≤5 peers at body size; longer or nested lists take a 3px black square, and a list whose items carry sub-lines takes no teal at all. Magnitude bars 6px, row label at 700, no chip inside a bar row. **Progress markers carry teal as a rail, not a disc (R28.2):** a completed step is a 22px white circle with a 1.5px black border and a black check, and the connector beneath it is 1.5px solid #1de9b6; ahead is the same circle with a mono numeral and a dotted #d9d9d9 connector; the current step is the one black-filled circle with the reserved teal offset. Four filled teal discs in a column outrank the steps they mark.
3. Fonts: Nunito (300–900) reading/display; JetBrains Mono for ALL labels/meta/timestamps/tables/badges/code. **Type floor 14px for Nunito. Mono sets at 12px, and a label recedes by weight and tracking, not by size (ratified 2026-09-06, R36.1, replacing R34.1/R34.2):** the render environment floors every font-size at 12px, so 11px and below paint at 12px and a size reduction below the floor is invisible. What made a label read large was never only its size: it was caps at 700 with .08–.1em tracking, which is optically wider and blacker than the 15.5px prose it annotates. LABEL mono 12px/**600**, caps, ls **.02em** — strings that are *scanned*: units, table headers, chip text, timestamps, provenance, section labels · IDENTIFIER mono 12px/600, verbatim case, no letter-spacing — any mono string that is *read*: metric identifiers in a cell, code, worked-example lines, field values in a register. Case and tracking separate the two roles; size never does. SECTION NUMBER mono — the `ss: NN` marker beside a section title — is 12px/400, ls .1em, no caps transform (it is already a numeral). A label at 700 or above .02em tracking is a violation, and so is any mono string at a size other than 12. Mono weight is a three-step ladder and nothing more: 400 quiet meta (a value beside its label, a caption) · 600 the label itself, **including every chip** · 700 reserved for a **bare emphasis run** inside a label row (`Owner Governance`, `W38 · now`) and the one active control in a set. A chip at 700 is a violation: a chip already carries a fill or a border, so weight has nothing left to mark. Verify labels with computed style, never with the authored value, and resolve the family through the element's ancestors: a label inherits `font-family` from its row and usually never names it. This governs mono in its **meta** roles; the one black display slab per section (rule 7b) is content, not meta, and sets its equation at 17px as part of that component. **Mono is scoped by section, not sprinkled per element (R35.2):** a section picks the CLASS of thing that is mono — its table, its code, its identifiers, its one label column — and everything else in that section is Nunito. A view where mono outnumbers Nunito has used it as decoration. Chips carrying words a reader reads (a touchpoint, a mood, a state name) are Nunito; chips carrying codes, units and ids are mono. **Two standing exemptions: the rule 17 nav pills, and the label of any control (R37.1) — a button, tab or pager label is mono 12/600 caps at .02em on every page, because a control label is the control's identity, not prose about it.** **Mono is meta-only (R19.2):** units, identifiers, timestamps, table headers, chip text, provenance. Never a heading of any kind. **Code is the one place hue enters ink (R36.6, replacing R23.15):** black on white, five token roles and no sixth — keyword #6a3ea1/700 · string #0e7a5f · numeral #a3441a · callable #000/600 · comment #000/300 italic; everything else black 400. Weight still carries the structure, so the palette is additive and a monochrome print of the block still reads. Hue on ink is legal inside a code surface and nowhere else. **Code is its own component, never a media variant (R36.10):** it carries a filename, a language badge and syntax, so it lives in a Code section beside the technology reference header, not among figures and video.
4. Greys structural only: #fafafa canvas · #fff surface · #f1f1f1 track ONLY — rails, progress/magnitude/score bars, segmented-control tracks, disabled fields, and media or figure placeholder zones (the one place a grey field stands in for content that has not arrived yet); **never a table header, never a row wash, never a button fill, never a node and never a content tile, anywhere** (R12.4/R20.2 — a tile is borderless #fff + S1; R36.5 retires the grey header row, the grey hover wash and the grey subtle-fill button: a header row is white under a 1.5px black rule, a row hover is rgba(29,233,182,.12), a quiet button is white with a 1px black border) · #ebebeb hairline (R8; #e4e4e4 retired) · #d9d9d9 dotted dividers/dashed annotation frames/**dashed diagram-canvas frames** (R12.5). **Zebra is retired (R35.3).** Table rows are separated by space and a 1px #ebebeb hairline — never by an alternating fill. Row padding is ≥14px vertical; a table that needs a stripe to be readable is a table with too little air in it.
5. Depth — two families (R8). SOFT = structure at rest, borderless white, never combined with a hairline: S1 rest `0 1px 2px rgba(0,0,0,.06)` · S2 card `0 4px 14px rgba(0,0,0,.08)` — one primary container per cluster · S3 float `0 14px 28px -6px rgba(0,0,0,.11)` (hero/chart/code frames, sticky rails). Page mix ≈60% hairline / 40% soft shadow. HARD = emphasis & interaction only: L1 hover lift (−1,−1 + 3px 3px 0 rgba(0,0,0,.18) + black border) · L1e static emphasis (1.5px black + 6px 6px 0 rgba(0,0,0,.08)) · L2 reserved teal offset (1.5px black + 5px 5px 0 #1de9b6) — AT MOST ONE untagged L2 per view, and **never on a surface carrying accent data marks: a chart is evidence, not a verdict (R23.8)** (docs specimens carry a dashed SPEC tag; zero is legal) · L3 overlay (10px 10px 0 rgba(0,0,0,.12)). **A third boundary inside a container's child is never drawn (R28.3):** a labelled pair inside a step, cell or card is a mono label with its value beneath it, no bracket and no frame. **One depth family per nesting level (R12.5): a container whose children carry shadows carries none itself — 1px dashed #d9d9d9 frame on #fafafa instead.** **A grid of peer cards on the #fafafa page canvas is borderless white + S1 — repeated outlines on the canvas read as noise (R20.1). A single standalone card may keep its hairline; a card on a white parent always does.** **A container is never fenced on one side (R36.4):** a left or top accent bar as a container edge is retired. A block that must carry emphasis takes L1e, the offset below and to the right; a block that must carry a semantic takes the label chip, and the tint sits behind the label, never behind the block.
6. Boundaries drawn once (R8). Content sub-blocks inside a module = 14×14 corner bracket (2px black L, top-left) + a T3 title above it — no fills, no outlines. **The title after a corner bracket is Nunito 700/17 sentence case, never a mono caps string (R35.4)** — this was the single most repeated breach in the library. The sub-block title is T3b, one rung under its container's T3 heading; mono below it is meta only (attribution, units, provenance), never the title itself. Sibling sections of ONE module share one surface, split by INSET hairline dividers (stop at content padding, never edge-to-edge); separate enclosures are for independent peers only. Diagram nodes/tiles are borderless white + S1 (R12.4) — #f1f1f1 is retired for nodes; de-emphasis is opacity (.55) with the shadow dropped, never a grey fill. Black borders stay reserved for markers (decision diamonds, DFD entities, the one emphasized node). Borders still never nest. **Tables carry no outline (R36.8):** borderless white at S1, radius 12; the title sits above the surface as a label with no rule under it; the header row is white under a single 1.5px black rule; body rows are separated by 1px #ebebeb hairlines at ≥16px vertical padding. A box drawn around a table adds a boundary the hairlines have already drawn.
7. Semantics = black text + mono label always, in **two intensities (R19.1)**: TINT is the default — hue at 16–30% on white, black text, NO border (ok rgba(0,230,118,.2) · warn rgba(255,214,0,.3) · crit rgba(255,82,82,.16) · info rgba(64,196,255,.22) · note rgba(179,136,255,.22)); SOLID — full fill (#00e676 · #ffd600 · #ff5252 · #40c4ff · #b388ff) + 1.5px black border — is the view's verdict, at most ONE per view. A semantic fill may NEVER serve as a heading or a column header. Neutral chip = white + 1px black border. Title blocks carry ≤3 status chips; aliases past four collapse behind a disclosure. Three exemptions from the tint default: a **token swatch** naming its own hex (that is the palette), a **data mark** with no label inside it (chart bar, legend square, lane swatch, progress segment), and an **interactive control**, which keeps its 1px black border as the affordance. **Labels come from the closed vocabulary** — eight callouts (Correction added R31), six status chips, three requirement levels, three check marks (R23.10), Selection ss: 01. A word outside it is not a label.
7b. Formula ration (R19.4, amended R36.7): ONE display slab per section, ≥24px padding, carrying that section's defining equation only — white surface, 1.5px black border, identifier mono at 17px. The black-filled slab is retired: a section's equation should read as its most precise statement, not its loudest mark. All other math is inline — mono on white, 1px #ebebeb hairline, radius 6. Raw arithmetic inside a sentence takes no chip; a chip means the token is named again elsewhere.
7c. Black fill ration (R20.3, tightened R36.7): the primary button · the one selected control in a set (active filter, active tab) · the current step marker · diagram terminals · on charts, axis and threshold lines plus at most one selected mark (R23.7). **Retired: black-filled status chips, black code surfaces, the black display slab, the black inline-code chip and all solid black banners.** Every reading surface is white; black fill is reserved for the thing the reader is meant to act on, so a page carries a handful of black marks, not a scatter of them. A status chip takes its semantic tint; an inline code token takes the white hairline chip; a full-width emphasis strip is a corner-bracket sub-block or white with a 1.5px black border.
8. Shape: pills (999) for ALL interactives; cards 14 · tables/tiles 12 · inputs 8 · chips 4 · code chips 6 · chart-bar caps 2–3. Never 5px or 10px.
9. Layout: 1060px grid · 70ch reading · 96px section rhythm · body 15.5/1.85 · **type floor 14px**, which is also caption and commentary size — a source line under a figure or table, an attribution, a specimen note. Reading prose is never set at the floor. **Two spacing scales, split by altitude (ratified 2026-08-27, R-h):** STRUCTURAL, module altitude and above — 16/20/24/28/32/48/88/96 (the former 26 exemption is retired: an ordinary container is 28 and a primary container 32, per rule 10) · COMPONENT, interior chrome (chip/pill/row/label/tick) — 2/3/4/6/8/9/10/12/14. A value from the wrong scale is a violation; 5 and 10 remain illegal as *radii* (rule 8), 10 is legal as component spacing. Sections: teal bar → `ss: NN` mono + 900 title → intro ≤70ch. **Part transitions (R19.3):** a quarter-document boundary gets its own full-width surface — part name 900/28px, pillar and section range in mono beneath, 96px clearance above. It outranks every section title within it, and is never set at label size.
10. Breathing floors (R8, raised R36.2): container interior padding ≥28 (primary containers 32) · mono label → content gap ≥12 · **a sub-section inside a container is separated from the one above it by 28px and an inset 1px #ebebeb rule, never by 12px of air** — the fields of a spec card, the pro/con list under a description, the result under its criteria, the footer line under a list · tile/card grid gaps ≥20 · content column gaps ≥28 · sibling surfaces ≥16 apart · list item gaps ≥12 · table row padding-y ≥16 · body line-height ≥1.75 at 14px and 1.85 at 15.5px · diagram gaps ≥14. When in doubt, add one 4px step. Alignment precision matters; no visual noise.
11. Focus: global 2px black ring, 3px offset (helmet reset). Interactives are real <a>/<button>/inputs — never clickable divs. Headings are real h1/h2 (margin:0, inline-styled); breadcrumb current = aria-current.
12. Responsive is structural (helmet media blocks, ids + !important): rails → top strip ≤1150 · data min-widths release ≤800 · 1fr grids stack ≤640 · tables scroll <641.
13. Containment (R19.7). Wrap material in a container only if it is one of ≥2 compared peers, a skippable aside, or an interactive surface. Sequential prose, numbered lists and single passages sit on the page. Never two container levels; a container is never a container's first child. **A dashed canvas never contains another dashed canvas (R35.5)** — nesting a frame inside a frame inside a frame is the failure this rule exists to prevent, and it recurs because each frame looks reasonable on its own. Before adding a frame, count the frames already above the thing you are framing; if the answer is one, do not add a second.
14. Composition order (R19.8, R19.9). A heading is never followed immediately by a container group — at least one sentence names the group first (a group following prose or another container already has context). Dividers separate siblings only: legal between two sibling sections sharing one surface, never heading-to-own-body, never between list items, never directly above or below a container. A divider is not a substitute for spacing.
14d. **Weight marks a phrase, never a sentence (R30.7).** Bold is a lead-in, a term or a clause — the moment a whole sentence is set at 700 the emphasis names nothing inside it. Where two passages must rank against each other, the lighter one goes to 300 and the heavier stays at 400; a full-sentence 700 is always the wrong tool.
14c. **One item, one paragraph (R27.8).** A list item never breaks into a title line plus a sub-line beneath it: the lead-in is bold and runs inline with its explanation in the same flowing line. The only sanctioned break inside an item is one level of nesting, which is containment. Applies to ranked, plain, paired and register lists alike.
14e. **No em dash in page copy (R36.9).** A dash joining two clauses is replaced by a colon where the second clause explains the first, a comma where it qualifies it, and a full stop where it is a second statement. Titles take a colon, not a dash. Attribution and provenance take a mono label, never a dash prefix. The en dash survives only inside a numeric range (16–30%).
14b. An edge label sits beside its line; an interactive branch control sits **above** it at 8px clearance, no halo (R20.4).
15. Ad-hoc diagrams use three fixed layouts (R19.10): single-column ladder · two columns with one join · decision gate. Nodes size to text, arrows run on layout axes, no absolute positioning. Material fitting none of the three becomes a table. (The named library families — sequence, ERD, journey, Sankey and the rest — carry their own geometry.)
16. Figures and chrome (R19.11). A figure carries a T3 title, one line of description above it, and provenance in mono below. Scrollbars: 8px, rgba(0,0,0,.22) thumb at radius 999 (rgba(0,0,0,.45) on hover), #f1f1f1 track — a scrollbar is chrome and never the darkest mark in its frame, declared once in the helmet. Sticky rail: ≤260px wide, ≤60vh with internal scroll, collapsing to a top strip at 1150px.
17. **Navigation is identical on every page and never varies with the page you are on (2026-09-02).** One sticky white bar: brand + page chip + five group pills in fixed order — Foundations · Components · Diagrams · Templates · Composition. Each pill carries a hover/focus dropdown listing **every page in that group, in the same order, on every page of the system** — a dropdown whose contents change by location is the defect this rule exists to prevent. The current group takes the active-tab treatment (white pill, 1px black border, 2px 2px 0 #1de9b6); the current page appears in its own dropdown as a #f1f1f1 pill at 700, not as a link. Dropdown items are Nunito 400/14 with the teal underline; pills stay mono caps and unmarked. ALSO IN <GROUP> strips are retired — the dropdown replaced them.
17b. **The page’s own section list is a table of contents, not navigation.** On a **library documentation page** it sits in its own container below the menu bar — #fafafa, 1px #ebebeb bottom hairline, not sticky — labelled ON THIS PAGE with the page’s ss: NN anchors. Never inside the menu container. **A template sample is a specimen of a delivered document, not a library page (R36.13), so its in-page navigation is the rule 16 sticky rail** — ≤260px, ≤60vh with internal scroll, released to a static row at 1150px — and the horizontal strip is the library chrome that a specimen does not carry. Either way the current item is marked by weight alone (R28.1). Anchor targets take `scroll-margin-top:78px`. The one sanctioned helmet exception for nav: `[data-nav-group] [data-nav-menu]{display:none}` + `:hover,:focus-within{display:block}`, since a descendant hover cannot be expressed inline.
17c. **Group membership is closed.** Foundations: Foundations · Icons · Print · Equivalents. Components: Structured · Prose · Wayfinding · Provenance · Charts · Interaction · Learning · Questions · Change. Diagrams: library · at scale · II technical · III experience · IV structure. Templates: index · T1–T11. Composition: Composition · Anatomy · Selection · Implementing · Exemplar. A new page joins a group or it does not ship.

18. Icons (ratified 2026-09-02, R33.1): ONE 24px outline family (Basil Icons community set), black at 1.5px, with a solid twin per shape. The accent enters as a **partial fill above a waterline at 13 of 24** — one constant for the whole family, never per glyph — drawn by clipping the solid twin under the unchanged outline, so a filled glyph and a plain one are the same shape. **Fill only at 20px and above · at most one filled glyph per view · never the only cue.** Four allowed placements: callout label 20px (fill) · empty state 32px (fill) · index or hub card 24px (outline only, a grid of peers never fills) · register row label 20px (outline only); where two meet in one view the fill goes to the higher. NEVER inside a sentence, a nav pill or tab, a table cell, a status chip, a button, or a list bullet. A glyph enters only via the **closed register at Icons ss: 04** — 23 concepts, one shape each: eight callout labels, three empty states, twelve index cards. Four admission conditions, all of which must hold: the concept is already a closed-vocabulary name, it repeats, the shape is unclaimed, and **its solid twin floods an area above the waterline** (on stroke-shaped glyphs — a check, a magnifier, a bolt — the outline covers the band and the fill is invisible, so those shapes stay out of the fill placements). A concept absent from the register takes no glyph. Spec: `content-morphia Icons.dc.html`.

## Deliverable pages are the design system, not a report on it
A page in this project is documentation an implementer reads to build correctly. It contains rules, specifications, limits and specimens — nothing else. Never put into a page: diagnosis of past work, defence or blame of an implementer, cost estimates, ratification status, options addressed to Wynt3r, round numbers, change history, or anything phrased as a reply to him. All of that goes in `content-morphia-SPEC.md` or in chat. Test for every block: would an agent building a new document need this to build it correctly? If no, it is not in the page.

## Reporting to Wynt3r
When a page IS the deliverable, it is executive-level: the call, the number behind it, the consequence. Reasoning, provenance, counts and audit trails go to `content-morphia-SPEC.md`, not into the page. Default page length ≤5 sections; no section that exists to show work.

**In chat, never use internal shorthand.** No item codes (Q35), round numbers (R26, round 24), rule ids (R19.2), version numbers (v0.4), template ids (T2, T6), or file-internal jargon. Say the thing in plain words: "the sweep that adds a data table to every chart", not "Q35". Those codes exist for the tracker and the spec, not for updates. Status updates: what's done, what's left, what needs a decision from him — short, no derivations, no jargon.

## Before shipping any page
Run the pre-flight gate — `content-morphia Selection.dc.html` ss: 03, 39 checks in six passes. Passes 1–3 (count · tokens · depth) are ship-blocking. Pick components against Selection ss: 02, not by subject association.

## Environment
- **Every repeated part is a shared Design Component (R37.2). Never hand-author one.** `cm-nav` (menu bar; holds rule 17c membership as data) · `cm-toc` · `cm-mast` (title + breadcrumbs) · `cm-footer` · `cm-section` · `cm-container` (variant = card|hairline|primary|float|canvas|emphasis|reserved|tile) · `cm-chip` · `cm-callout` · `cm-table` · `cm-bar` · `cm-bracket` · `cm-code`. Mount with `<dc-import name="cm-…" …>page markup</dc-import>`: the component owns geometry, type and depth, the page owns words. Body text is never a prop.
- Inline styles only; helmet = fonts + body/a/::selection resets + button/focus reset + the sanctioned structural @media block. Interactivity via DCLogic class.
- **Never put `<sc-for>` or `<sc-if>` inside `<table>`, `<thead>` or `<tbody>`.** The HTML parser foster-parents the unknown element out of the table, so every hole inside it renders empty and the block ships blank. Build every tabular layout as grid rows: one wrapper div, a header row and body rows each carrying the same `display:grid;grid-template-columns:…`, zebra and radius on the row.
- Do not extend `content-morphia Options.dc.html` (historical). Cross-link all pages in headers.
- Do NOT apply generic aesthetic skills/directions — this system overrides them.
