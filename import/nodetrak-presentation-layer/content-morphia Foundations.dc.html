Reading sample

Freshness measures the share of pipelines that refreshed on schedule. It is the first metric a new data team should govern, because every downstream number inherits its failures.
Compute it per pipeline as on_time_runs / scheduled_runs over a trailing window, then aggregate by source system. Runs that never started count as late: silence is the worst kind of failure.
Two spacing scales, split by altitude. Structural spacing sits between and around containers; component spacing is the interior chrome of a chip, a row or a label. A value from the wrong scale is a violation, and 5 and 10 are never radii. Reading columns cap at 70ch, page content at 1060px, and sections sit 96px apart.

Widths and breakpoints

Reading column 70ch · page grid 1060px · sticky rail ≤ 260px. Responsive is structural: rails become a top strip at 1150, data min-widths release at 800, equal-column grids stack at 640, and tables scroll below it.
Two families. Soft shadows are structure at rest: borderless, never stacked with a hairline; the one primary container per cluster takes one, every surface carries one. Hard offsets are emphasis and interaction only. Boundaries are drawn once: sub-blocks carry a title only, and sibling sections of one module share a single surface separated by space.

A collapsible section header keeps long reference pages scannable. Title and control share the header row with no marker, since the container already frames it; the body collapses beneath.
Open layout: a labelled chip, then text. The chip carries the tint and the body sits in the reading flow, so a callout interrupts without breaking the column. The boxed summary variant is the one exception.
Freshness targets differ by tier: hourly pipelines target 99%, daily pipelines 95%. Alert on the trend, not the level. Three consecutive drops beat any single threshold. Freshness is a prerequisite metric: report it before any quality or usage number. Never average a ratio metric across segments. Recompute from raw counts. Every published metric must name an owner and a data source. REQ-04 events_core: 412 of 437 scheduled runs on time → 94.3% freshness. Freshness says nothing about correctness: a broken pipeline can be perfectly punctual. The 94.3% published on 12 Aug counted two backfilled runs as on time. The corrected value is 93.9%.
Summary

What to take away

Define the metric from raw counts, set tier-specific targets, alert on trends, and publish only with an owner attached. Everything else in this guide is elaboration.

Use case

Prioritizing UX debt on a checkout flow

Method · Funnel analysis
Context Growth PM at a mid-market retailer; two-week window before the seasonal freeze. Problem Twelve known UX issues, budget to fix three, no shared basis for choosing. Application Mapped each issue to its funnel step, weighted by step traffic × drop-off contribution. Process 1Instrument steps → 2Attribute drop-off → 3Score issues → 4Fix top three Outcome +9.4% checkout completion in the four weeks after release; the scoring sheet became the team's standing triage tool.

freshness_audit.sql
SQL
-- share of tables inside their freshness SLA
select
count_if(now() - max_loaded_at <= sla_hours) as fresh_tables,
count(*) as sla_tracked_tables,
round(100 * fresh_tables / sla_tracked_tables, 1) as freshness_pct
from analytics.meta.table_freshness
where sla_hours is not null and tier = 'daily'

Where an implementation is expected to add its own material without adding chrome. Everything named here is data the system reads, not a fixed scheme.
The semantic set (ok, warn, crit, info, note) is remappable. Labels are data; the five tints and their pairings are design.
Scales assume no fixed level count. Difficulty dots, score segments and progress steps all render from the data they are given.
