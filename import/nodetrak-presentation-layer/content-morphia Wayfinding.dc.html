The index nests further than a breadcrumb can describe, so arrival is not the same problem as navigation. These five components carry it: search over nodes, facets over their properties, ranked entry points, and the two controls that make an updated node legible — a version selector and a diff.

Search returns nodes, not pages. A result therefore has to answer three questions at once: what kind of thing this is, where it sits in the index, and how well aggregated it is — because a node with forty sources and one with three hundred are not the same answer to the same query.
The field carries a scope control. Scoping to a pillar is the cheapest way to cut a broad query, and it is stated in the result count rather than left in the control.

Nothing in the index answers this. The empty state names the two recoveries rather than apologising: widen the scope, or enter through the nearest branch.
A result row is fixed in four parts and admits no fifth: type chip and path, title, one snippet line, and the aggregation meta. Matched terms take a teal wash, which is legible only because the query sits directly above it and the match count is stated in the meta line.
A facet is a fact about a node — its type, its pillar, how well evidenced it is. It is never a topic; topics are the index itself, and duplicating them into a rail gives two conflicting maps of the same thing.
Counts recompute against every other group but never against a facet's own group, so selecting one value does not zero its siblings. A value that reaches zero stays visible and disabled: removing it would quietly change the shape of the index the reader is learning.

No node carries every selected facet. The rail keeps its zero counts visible above, so the combination that failed can be read off directly and one value dropped.
Selections are restated above the results as removable pills. The rail alone is not enough: at 1150px it collapses to a top strip and, on a long result list, scrolls out of view entirely.
Readers who arrive without a query need a way in that is not the root of the tree. Two lists do it, and they answer different questions: what the practice reads, and what the index has learned since the last visit. Both state the window they were computed over, because a ranking without one is a claim with no bounds.

Rank is a mono ordinal in its own column, never a badge — a badge would compete with the type chips that carry meaning elsewhere. Recency is a date, not a NEW flag: the reader's last visit is unknown, so only the absolute date is honest.
A node re-aggregates on a cadence, so a reader returning to it is reading a different document from the one they left. Two controls make that legible: a selector naming which version is on screen, and a diff naming what moved between two of them.
A diff describes meaning, not presentation. Three kinds are permitted — added, removed, revised — and each is a tint with its own mono label, so the kind survives being read without colour.
