# Expanded Content Taxonomy Reference — Completion Checklist

*Source: Expanded Content Taxonomy Reference (prepared June 22, 2026). Converted to a checklist so each section, sub-section, and table row can be tracked as complete.*

**How to use this doc:** Check off `[x]` each item once that content type, module, component, object, field, or blueprint step exists and is implemented. Items are grouped exactly as they appear in the source document (Sections 0–14), including all tables and the condensed master list.

---

## 0. Classification Dimensions

- [ ] Granularity — the level at which the content exists (site, collection, page, section, module, component, atom)
- [ ] User intent — what the user is trying to accomplish (learn, compare, solve, buy, verify, navigate, troubleshoot)
- [ ] Content purpose — the strategic job of the content (educate, convert, support, prove, entertain, retain)
- [ ] Format — the surface form (article, video, table, chart, calculator, glossary, checklist)
- [ ] Structure — how the information is organized (linear, hierarchical, matrix, chronological, interactive, modular)
- [ ] Freshness need — how often it must be updated (evergreen, seasonal, real-time, versioned, campaign-based)
- [ ] Evidence type — what supports the claim (expert opinion, data, citation, testimonial, experiment, benchmark)
- [ ] Interaction level — how passive or active the experience is (static page, filterable table, quiz, dashboard, playground)
- [ ] Distribution channel — where the content lives (website, app, email, social, PDF, docs, webinar, sales deck)
- [ ] Measurement model — how success is evaluated (organic traffic, engagement, leads, activation, retention, deflection)

## 7. Content Structures

- [ ] Linear — information follows a sequence
- [ ] Hierarchical — parent-child organization
- [ ] Hub-and-Spoke — central page links to detailed subpages
- [ ] Matrix — multiple entities compared across attributes
- [ ] Chronological — organized by time
- [ ] Question-Answer — organized around user questions
- [ ] Problem-Solution — starts with pain point, ends with resolution
- [ ] Before-After — shows transformation
- [ ] Decision Tree — routes users conditionally
- [ ] Reference Lookup — optimized for quick retrieval
- [ ] Narrative Arc — builds context, conflict, resolution
- [ ] Modular Blocks — sections can be reused or rearranged
- [ ] Interactive Input/Output — user input changes the output
- [ ] Faceted Browsing — users narrow a large set through filters
- [ ] Progressive Disclosure — reveals complexity gradually
- [ ] Scrollytelling — narrative unfolds through scroll and visuals

## 14. Practical Takeaway

- [ ] Macro level defined and applied — "What kind of destination is this?" (pillar page, category page, tutorial, case study)
- [ ] Meso level defined and applied — "What job does this section perform?" (definition, comparison, proof, troubleshooting)
- [ ] Micro level defined and applied — "What UI pattern renders it?" (table, card, callout, list, chart)
- [ ] Nano level defined and applied — "What atomic data does it contain?" (term, metric, quote, link, field, label)
- [ ] Content model avoids treating pillar pages, tables, FAQs, charts, and CTAs as peers (they exist at different levels)
- [ ] Mapping confirmed: Pillar page = macro container
- [ ] Mapping confirmed: FAQ = meso module or page type, depending on scope
- [ ] Mapping confirmed: Table = micro component
- [ ] Mapping confirmed: Metric value = nano object
- [ ] Mapping confirmed: CTA label = nano object inside a conversion component
